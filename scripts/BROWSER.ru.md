# Проверка с Prettier standalone в браузере

Плагин можно собрать вместе с [Prettier standalone](https://prettier.io/docs/browser). Сборщик должен учитывать поле `browser` зависимостей; проверка использует esbuild с `platform: "browser"` без Node-polyfills и пользовательских заглушек. Это проверка собираемого пакета, а не готовая браузерная поставка и не проверка развёрнутой песочницы.

```js
import * as prettier from "prettier/standalone";
import postcssPlugin from "prettier/plugins/postcss";
import sorter from "prettier-grundy-scss-order";

const result = await prettier.format(".card { width: 1px; color: red; }", {
    parser: "scss",
    plugins: [postcssPlugin, sorter],
    grundyScssSorterSafety: "strict"
});
```

Standalone требует явно передать плагины: штатный PostCSS-плагин предоставляет принтер, а сортировщик указан последним, чтобы заменить SCSS-парсер. Настройки передаются непосредственно в вызов; standalone не ищет конфигурационные файлы и ignore-файлы. Оба режима, алиасы и пресеты используют те же публичные опции, что и Node.js.

## Карты исходников

Браузерные перенаправления самого PostCSS отключают файловые/path API и `source-map-js`. Поэтому браузерный парсер не декодирует предшествующие inline- или внешние карты. Обычный вход проходит через direct; корневой комментарий `sourceMappingURL` по-прежнему выбирает Processor fallback. Вложенная аннотация сама по себе не включает fallback в браузере, поскольку разобранной предшествующей карты нет.

Fallback сохраняет браузерное поведение установленного Processor. В проверенной сборке PostCSS 8.5.33 аннотации сохраняются без изменений; более ранняя поддерживаемая сборка может удалять корневые аннотации. Node.js может разбирать/перегенерировать карты и отклонять некорректные или неподдерживаемые кодировки, которые браузер оставляет комментариями. Отчёт выделяет эти различия отдельно и сравнивает CSS после удаления map-аннотаций. Для остальных случаев обязательны побайтное совпадение Node/browser или одинаковая диагностика.

Сохранённые аннотации могут описывать исходный вход и устареть после сортировки/печати. Ни одна среда не гарантирует, что итоговая карта описывает вывод принтера Prettier. Эта проверка не добавляет поддержку карт в браузере, файловые заглушки или новую политику runtime.

## Запуск из репозитория

```sh
npm ci
npx playwright install --with-deps chromium
npm run test:browser -- --output browser-results.json
```

Команда упаковывает текущий checkout, устанавливает tarball и выбранную версию Prettier в отдельный временный consumer, собирает браузерный bundle, получает независимые эталоны Node.js и запускает headless Chromium на loopback-странице. Временный consumer удаляется после завершения. Playwright и esbuild — только devDependencies.

Для уже установленного пакета, включая опубликованную версию, укажите `--package-root /consumer/node_modules/prettier-grundy-scss-order`. Используются Prettier и PostCSS этого consumer. Для ручного открытия браузера есть `--serve`: команда выводит локальный URL, ожидает результаты страницы и не запускает браузер или отладчик. В PowerShell используйте `npm.cmd`, если обёртка поглощает `--`.

312 случаев охватывают все 15 закреплённых регрессионных fixtures с пятью пресетами и strict/loose, BOM/CRLF, пустой вход и только комментарии, привязку комментариев и ignore, сочетания root/group spacing, алиасы, ошибки конфигурации/синтаксиса и root/nested/missing/inline/malformed map-аннотации. Каждый успешный результат сравнивается с явным эталонным путём через Processor и повторным форматированием. В разреженных сгенерированных картах при сравнении двух Node-путей нормализуются только случайные PostCSS input source IDs; CSS без карт отдельно сравнивается между средами. Пустой вход может обрабатываться fast path самого Prettier без вызова парсера.

`browser-results.json` содержит версии пакета/зависимостей, хеши bundle/входа/исходников, окружение браузера, хеши вывода и счётчики direct/fallback каждого случая. Соседний каталог `browser-results.evidence` сохраняет исходные результаты Node/browser, случаи, metadata и собранный bundle. Несовпадение завершает проверку с ошибкой. Unit-тесты ловят неполное/дублированное покрытие, потерю комментариев/изменение вывода, неверный путь интеграции и исключения для карт, меняющие CSS.

CI запускает проверку в существующей матрице Node.js 24/Linux с минимальной Prettier 3.8.1 и последней 3.x. Каждый прогон сохраняет отдельный артефакт `browser-results-prettier-*` с отчётом и JSON evidence на 14 дней. Bundle и отчёты исключены из npm-пакета. Это smoke в Chromium; проверка не гарантирует поддержку всех браузерных движков, не измеряет производительность и не доказывает семантическую эквивалентность произвольного Sass/CSS.
